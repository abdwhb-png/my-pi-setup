# E3: F2 adoption and demand-loaded Auto Translate

## Implemented scope

F2 is now applied to `agent/extensions/sandbox/runtime/runtime-bundle.ts`. Its production source is byte-identical to the final evaluated proposal. Files larger than 1 MiB use a reusable 1 MiB buffer, preserving complete SHA-256 verification, cancellation checks, descriptor draining, the eight-worker bound and the existing admission deadline. Six regression cases from the proposal now live beside the resolver.

U2a is the only extension-loading candidate selected by the user. Auto Translate still registers its commands and reads trusted configuration immediately, so configured language commands remain available. Its widget is now loaded only by activation, and its translator/provider client is loaded only for an eligible input after activation. Pi Session Recall is user-owned and explicitly deferred. Other entries in the previous inventory are outside this change.

## Auto Translate behavior

The extension starts disabled. `/translate-on` and `/translate-to-<code>` activate it and load the widget. `/translate-send` changes send/display mode without activating translation. `/translate-off` hides the widget and resumes pass-through. Blank input, extension-injected input and missing-model input do not load the translator. Translation returns to off at session start and shutdown.

The existing command refresh callback now supports asynchronous loading and commands await it. The widget is created at most once per extension instance, including concurrent activations. Loaded modules are reused, not unloaded on disable. Configuration/model selection, saved project trust, translation prompts, authentication, send/display semantics and error reporting retain their existing behavior. No new setting or general-purpose loader was added. See the [extension README](../../agent/extensions/auto-translate/README.md).

## Validation

V1: Before applying F2 production code, the new bounded-hashing test failed on a 3,145,747-byte hash update. After applying it, all 53 targeted sandbox tests passed, covering distribution integrity, short final blocks, cancellation/read/close draining, I/O failures, backend deadlines and preparation supersession. The run used Bun's 15-second test budget to avoid the previously documented 5-second harness timeout under contention. Production deadlines were unchanged.

V2: Before changing Auto Translate, its loading test found the eagerly imported translator and its activation test found an eagerly contributed widget. After the change, all 44 extension tests passed. The factory test additionally passed with concurrent activations and shutdown hiding. The real Pi/Jiti test exercised the public entrypoint and real command/input pipeline, replacing only the completion endpoint with a local HTTP fixture. It covered first translation, display mode, disable/re-enable, target selection and session reset without a real provider request. Existing saved-trust coverage passed.

V3: Focused TypeScript checking passed. Repository-context focused Oxlint passed with warnings, including intentional sequential reads in the bounded hash loop. The temporary prototype's unresolved-type lint limitation did not recur in the repository. `bun run lint:boundaries` passed after the import changes. The repository formatter ran on the three changed production files. No full-repository test suite, global typecheck or whole-CLI/TUI timing was run.

V4: The real installed-bundle qualification passed through the active sandbox extension with all 16 assertions. Startup admission took 2.779 s and replacement preparation took 3.264 s, both below the unchanged 20-second acceptance threshold. Both `safe_bash` marker commands reported sandboxed Zerobox execution and exit code zero. Explicit shutdown completed. This is one new qualification sample, not a comparative speedup claim or an override of earlier contended failures.

## Auto Translate loading measurement

Eight isolated loader processes alternated before/after as `A B B A A B B A`, with the first pair retained as warmup and excluded from medians. Each process used the same promoted Pi loader, CPU affinity `6,7`, temporary agent configuration, and `JITI_TRY_NATIVE=false`, matching the earlier isolated-loader protocol. The same four default commands registered in every sample. Filesystem/transformation caches were not cleared and the host was not exclusive.

| Metric, three measured samples per version | Before | After |
| --- | ---: | ---: |
| Median import plus factory time | 828 ms | 793 ms |
| Range | 725–967 ms | 775–866 ms |
| Median CPU pressure | 14.64% | 13.82% |

These overlapping ranges do not establish a reliable startup speedup. The demonstrated improvement is that unused translation and widget dependencies are no longer loaded by this extension, with first use still working. Configuration and command registration remain eager. No whole-Pi startup saving or first-use latency guarantee is claimed.
