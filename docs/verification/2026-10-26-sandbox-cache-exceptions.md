# Scoped sandbox cache writes

The sandbox previously denied every write covered by `node_modules/*`, including Vite's generated configuration under `node_modules/.vite-temp`. Both `bash` and `safe_bash` follow the selected execution mode, so changing tool names did not bypass that filesystem boundary.

## Permission contract

`filesystem.denyWriteExceptions` associates an existing denial glob with literal paths. Exceptions are globally authorized and inherited by default; project and session layers can only select authorized entries or disable them with an empty array. Ordinary write authority is still required. Each exception modifies only its referenced rule, preserving other matching denials and read restrictions. The engine validates literal paths, checks requested and resolved destinations, and retains rename and hard-link source checks. Basename denial globs such as `*.key` keep their documented recursive scope after Pi canonicalizes the policy.

The proposed global selection covers five generated directories beneath `node_modules`: `.vite-temp`, `.vite`, `.cache`, `.vue-global-types` and `.tmp`. Their uses were verified in project configurations and installed Vite/Vitest, Nuxt, Jiti, Laravel Vite and Vue tooling. Package directories, `.pnpm` and `.bin` are not exempted.

## Runtime evidence

Admission schema 3 carries the exact exception pairs. Pi verifies the receipt before dispatch and rejects missing or widened exceptions. Existing configurations retain schemas 1 and 2. Native refused writes are collected by the same filesystem enforcement code and reported through bounded terminal status metadata. Pi does not infer a confirmed denial from stderr or reimplement the native glob matcher. Failed shell context also identifies the observed execution mode while preserving raw output. Removing an exception revokes existing executions through the authority watcher.

## Native CI preparation

The first native run failed before tests because its source reconstruction still targeted Pi 0.87.1, while the harness lockfile references the promoted Pi 1.1.0 packages. CI now restores the exact daily archives from a checksummed fixture and keeps lockfile integrity unchanged. The test harness comes from its existing registry pin. A successful run archives its qualified runtime so local promotion can use the binary actually tested on the native kernel.

The next native run passed 1,230 tests and exposed four existing failures. All four were reproduced on the unchanged pre-feature commit with the project-pinned Bun 1.3.14. The shell wrapper raced interruption against the operation's own cancellation path, returning before final provenance and process cleanup. Removing that outer race preserves the shared deadline while awaiting the owning operation. Existing timeout, abort and preparation-deadline tests pass afterward.

Two lifecycle tests also needed explicit synchronization. The concurrent-edit fixture used a Bun promise matcher inside its launching helper, blocking before it could release its deferred initialization; it now launches the real operation directly and verifies the superseded-startup error, successful replacement and output. The expiry fixture waits for the observable replacement instead of assuming eight microtasks are enough. The three affected test files now pass all 78 tests. These repairs preserve the native CI gates rather than excluding existing failures.


A subsequent native run passed the Pi boundary suites and built the engine, then correctly rejected a builder package drift: bootstrap installation of CA certificates had upgraded `libssl3t64` from the pinned image's version to a live repository version. The builder now mounts the runner CA bundle read-only for transport and uses the locked Ubuntu snapshot directly. It installs no bootstrap package and retains all package-version and archive checks. The new orchestration regression failed before the change and passes afterward; a real pinned-image probe verifies snapshot TLS access while preserving the original OpenSSL package version. The builder-specific relocation tests require `patchelf`, absent on this host, and run inside the pinned CI builder.
