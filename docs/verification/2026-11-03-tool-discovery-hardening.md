# Portable host tool discovery hardening

The published `setup-2026-11-03.2` bootstrap treated missing PHP search directories as required resources. The independent code review additionally reproduced invalid retained executable permissions. Earlier qualification installed distro PHP and Composer before its mise branch and did not cover either negative case. This report describes subsequent development changes; it does not extend the qualification of the published archive.

## Corrected behavior

PHP includes only existing absolute include directories and an existing extension search directory. Loaded configuration files and executable dependencies still require valid resources. Node, Bun, Python, Go, PHP, Composer and pnpm share executable checks for fresh candidates, resolved launcher targets, retained bindings and explicit bindings. Retained commands must remain executable, satisfy the existing writable-file policy and be covered by their authorized command directories and file selections. Ambient PATH fallback cannot repair a stale binding. Their concrete identities are watched until publication.

Parameterized regressions cover all seven commands: lost execution permission, unsafe writable commands, disappearance, redirected aliases, unselected files in explicit bindings, missing required resources, overly broad grants, malformed metadata and successful reuse without ambient PATH. Public configuration CLI checks also verify that unusable bindings cannot pass check/apply or change stored authority. Pure discovery tests remain independent of an installed Pi SDK; authority-publication tests retain their coverage in the owning development setup suite.

## CI changes

The existing qualification script separates common prerequisites from system-only PHP, Composer and Go. HOME and XDG selectors belong to the disposable destination. A tools-only mode runs discovery contracts and fixture regressions before Pi provisioning. Actual executable origins, versions, grants, missing-command outcomes and runtime startup checks are recorded as structured evidence.

Two fresh Ubuntu container jobs prepare system and mise layouts independently, without runner development tools. Their base image digest was checked against the official Docker Hub Ubuntu 24.04 tag metadata before configuration. The pinned dev-tools revision intentionally supplies PHP through APT and links it into mise; the canonical origin check documents that exception. Both clean jobs must pass before native Ubuntu and WSL2 sandbox qualification proceeds. Qualification triggers now follow `develop` and `main` rather than obsolete task branches. Real PHP fixtures test missing search directories independently of system PHP resources.

## Local evidence and limits

Verified RED cases covered a missing PHP extension directory, retained non-executable commands for all seven command names, non-executable resolved launcher targets for all seven, unsafe mise targets executing before validation, and inappropriate kernel writes during tools-only preparation. The follow-up review found the last two cases; their targeted regressions failed before correction and passed afterward. Unsafe mise targets are now checked before the metadata probe, and tools-only mode skips kernel tuning reserved for native sandbox jobs. Focused GREEN verification initially passed 92 tests with 346 assertions across six files. The complete portable operator regression suite subsequently passed 252 tests with 963 assertions across 24 files, including runtime lifecycle and installation interactions. Agent and qualification-script typechecks passed, as did the extension boundary graph and boundary lint. Scoped lint completed without errors; existing discovery-module warnings remain. The workflow YAML, its embedded shell blocks and shell script syntax were checked. Executable shell tests with disposable fake package managers verified both preparation paths, refusal to continue into Pi installation, and absence of kernel-setting writes in tools-only mode. The kernel-control fixture reports both optional procfs knobs as present, so the assertion remains effective on hosts where those knobs are absent. Dependency graph checks confirmed that clean-container contracts and pure discovery tests need no installed third-party package.

No real host tool installation, Pi installation, sandbox qualification, provider generation or VPS action ran on this workstation. PHP interpreter probes used a temporary copied interpreter and isolated configuration. The new GitHub Actions jobs have not yet run. Their first successful real execution remains required before claiming the corrected setup is qualified or publishing a replacement release.
